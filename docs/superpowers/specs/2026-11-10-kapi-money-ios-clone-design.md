# Kapi Money（咔皮记账）iOS 1:1 原生全量复刻设计文档

- **日期**：2026-11-10
- **目标平台**：iPhone (iOS 16.0+，适配灵动岛与 Safe Area，支持 iOS 16/17/18+)
- **开发工具链**：纯原生 Swift 6 + SwiftUI + Swift Package Manager (`Package.swift`) + `xtool` (`xtool.yml`)
- **参考基准**：用户提供的 54 张 Kapi Money 真实机内截图（`IMG_2240.PNG` ~ `IMG_2294.PNG`）

---

## 1. 意图与背景 (Intent & Why)

用户希望在 iPhone 上拥有一款与 **Kapi Money（咔皮记账）** 界面、配色、功能、分类体系和交互体验 **1:1 完全一致** 的纯原生记账 App，拒绝 Web App 包装，要求采用原生 SwiftUI 并通过 `xtool` 构建。

同时，由于用户日常记账“怕麻烦”，特别要求强化 **iOS 快捷指令（Shortcuts）自动截屏记账闭环**：在支付成功页（如 TNG eWallet、银行转账或微信/支付宝页面）触发快捷指令后，自动截屏并交由 App 识别，在屏幕顶部弹出识别结果卡片并提供 **「修改 (View)」** 和 **「确认 (Got it)」** 两个按钮——点「确认」直接后台入账，点「修改」则直接跳转到 App 内的账单详情/编辑页进行调整。

## 2. 目标、非目标与反目标 (Goals, Non-Goals & Anti-Goals)

   - 默认主货币为 **马来西亚令吉 `RM (MYR)`**，同时支持多币种切换（`MYR / CNY / USD / SGD` 等）。
   - 预置用户截图中的真实账户（`现金`、`CIMB`、`TNGewallet`、`PBBank`）、默认账本 `Main Ledger` 及示例/初始结构。
2. **全量核心页面与功能模块**：
   - **首页「记录」页**（月预算剩余进度条、今日可用环形图、分类预算展开、净资产 30 天趋势可折叠抽屉、按日分组账单流水、底部全局常驻「🦫 任何事情都能问我 `+`」悬浮栏）。
   - **左侧抽屉导航菜单**（用户资料与 VIP/Pro 标识、当月打卡热力日历与记录天数/总记录/连续天数统计、7 宫格功能入口：图表统计/资产管理/账本管理/预算管理/小组件/分类管理/标签管理、3 宫格快捷记账：导入导出/自动记账/定时记账、设置）。
   - **手动记账 ⇄ AI 助手双模底部大面板**（右上角一键互切；手动记账支持支出/收入/转账、一二级分类网格、日期/账本/账户/计入收支/标签胶囊、备注与相册/拍照多图附件、带 `+`/`-` 算术运算与「再记」的自定义数字键盘；AI 助手支持预设气泡、一句话拆多笔自然语言记账、图片识账及表格化财务问答）。
   - **账单详情与编辑弹窗**（实付金额、分类、备注+小票原图缩略图管理、账单时间、付款账户、所属账本、添加优惠、添加退款/返现、交易方、删除账单）。
   - **全部记录（日历热力视图）**（月支出/月收入/日均统计条、收支/支出筛选、回今天按钮、收入橙/支出蓝多级深浅热力月历网格、单日最大支出金币皇冠角标、选中日期下方联动展示当日明细）。

   - **资产管理与账户详情页**（净资产/资产/负债总览卡、待报销管理、账户列表与添加账户；账户详情页支持余额直接修改、记账/转账快捷入口，以及 **「📅 明细（带 `记`/`改`/`删` 操作审计标签与变动后实时余额）」⇄「🧾 账单（按月/按日分组流入流出）」** 双视图切换）。

3. **AI 双模引擎（端侧原生免配即用 + 可选云端大模型 API）**：
   - **端侧引擎（默认零配置离线可用）**：利用 iOS 原生 `Vision` (`VNRecognizeTextRequest`) 进行截图/小票 OCR（针对 TNG eWallet、PBBank、CIMB、微信、支付宝账单页面专项规则适配），结合原生 `Speech` 语音识别与本地中文/英文自然语言分词拆单引擎（支持一句话拆多笔、识别金额、时间、账户和分类）及本地统计问答引擎。
   - **云端大模型引擎（可选增强）**：在「设置」中支持配置兼容 OpenAI 格式的 API（DeepSeek / OpenAI / Gemini 等），开启后复杂口语算术推理（如多人 AA 制）和深度 AI CFO 复盘自动调用大模型，失败或未配置时无缝回退端侧引擎。
4. **iOS 快捷指令（Shortcuts / `AppIntents`）自动截屏记账双按钮闭环（`IMG_2294`）**：
   - 基于 `AppIntents` 实现自动注册的系统快捷指令与 `SnippetIntent` 顶部弹窗卡片：传入屏幕截图后自动 OCR 识别并创建待确认/已识别账单，在当前屏幕顶部弹出与 `IMG_2294` 一致的卡片，提供 **「修改 (View)」**（点击通过 Deep Link / `openAppWhenRun` 直接打开 App 进入该笔账单的详情编辑弹窗）和 **「确认 (Got it)」**（点击确认入账并直接关闭弹窗，留在当前应用）。

### 2.2 非目标 (Non-Goals)
- **多端实时云同步后端与多人在线联机账本服务**：不自建远程中心化账号服务器；账本管理支持本地创建切换多个独立账本（如个人、家庭、旅行）以及通过 CSV/JSON 导入导出共享。
- **App Store 内购付费墙（IAP）**：不设任何收费限制，默认解锁全部 `Pro / VIP` 高级功能（如无限账本、AI 助手、分类预算、资产趋势等）。

### 2.3 反目标 (Anti-Goals)
- **绝不使用 Web App / WebView 套壳**：禁止使用 HTML/CSS/Capacitor 伪装原生界面，必须 100% 使用原生 SwiftUI 视图构建。
- **绝不依赖付费 Apple Developer 专属 Entitlements（如 CloudKit / Push Notifications）才能编译安装**：必须确保普通免费 Apple ID 通过 `xtool` 或自签名工具（SideStore / AltStore / Sideloadly / TrollStore）即可顺利签名安装到真机。
- **绝不让快捷指令必须手动填写复杂参数才能运行**：快捷指令必须做到截屏即识别、一键点「确认」或「修改」。

## 3. 约束条件 (Constraints)

1. **开发环境与跨平台构建约束**：
   - 当前宿主环境为 Windows，工程必须严格遵循 `xtool` 标准目录结构（根目录包含 `Package.swift`、`xtool.yml` 及 `Sources/KapiMoney/`）。
   - 同时提供 Windows WSL2 下的 `xtool` 构建辅助脚本与 `.github/workflows/build-kapi-ios.yml` 云端自动编译打包 `.ipa` 工作流。
2. **免费签名权限约束**：
   - 快捷指令 `AppIntents` 直接编译在主 App Target 内（In-App Intents，iOS 16+ 原生支持），这样快捷指令与主 App 共享同一个沙盒目录与 `UserDefaults.standard` / 本地存储文件，无需依赖付费开发者账号专属的 `App Groups` Entitlement，免费个人 Apple ID 也能 100% 正常使用快捷指令与主 App 数据互通。

## 4. 方案对比与选型 (Approaches)

在设计阶段我们评估了以下两种构建与落地方式，并由用户选定 **方案 A**：

### 方案 A（已选定）：标准 `xtool` 原生 SwiftUI 工程 + 双通道构建（WSL 本地 `xtool` 直装 + GitHub Actions 云端自动出 `.ipa`）
- **核心设计**：
  - 使用标准 SwiftPM (`Package.swift` + `xtool.yml`) 组织纯原生 SwiftUI 代码。
  - 将 `AppIntents`（快捷指令动作与 `SnippetIntent` 交互卡片）内置于主 Target 中，免除付费 App Group 权限限制。
  - 提供 WSL2 `xtool` 构建脚本，同时配置 GitHub Actions (`macos-14`) 自动编译生成未签名/可自签名的 `KapiMoney.ipa` Release 产物。
- **优势**：100% 满足原生 SwiftUI + `xtool` 要求，且无论用户本地是否立即配好 WSL2 + USB 转发，都能立刻拿到 `.ipa` 安装包在 iPhone 上安装使用。

### 方案 B（未采用）：仅使用本机 WSL2 + `xtool` 本地编译装机
- **取舍原因**：完全依赖在 Windows 本地从零安装 WSL2 Ubuntu、Swift 6 工具链与数 GB 的 Darwin SDK 并通过 `usbipd` 桥接 USB，首次环境准备耗时长且缺少云端 `.ipa` 兜底通道。

### 5.2 账户、资产与操作审计明细（1:1 还原 `IMG_2258`~`IMG_2262`）
- **默认资产账户**：
  - `现金`（现金余额）
  - `CIMB`（其他银行储蓄卡余额）
  - `TNGewallet`（自定义余额）
  - `PBBank`（其他银行储蓄卡余额）
- **资产与账单联动 + 审计日志（`账户明细` 双模式）**：
  - 每次新增（`记`）、修改（`改`）、删除（`删`）关联了某账户的账单，或手动修改账户余额时，系统自动更新账户当前余额，并写入一条 **账户变动审计记录（`AccountAuditLog`）**。
  - 在「账户详情」页右上角切换 **`📅 明细`** 与 **`🧾 账单`**：
    - **`📅 明细` 视图（`IMG_2259`, `IMG_2260`）**：按操作发生的时间轴倒序展示，左侧显示操作时间（如 `23:55`）与圆角状态徽章——蓝底蓝字 **`记`**（新增入账）、粉底橙字 **`改`**（账单编辑）、灰底黑字 **`删`**（删除账单，金额带删除线如 `~~RM5.90~~`），右侧显示该次操作后的实时快照余额 `余额: RM68.62`，下方显示备注与原账单日期 `📅 账单日期 2026.11.08`。
    - **`🧾 账单` 视图（`IMG_2261`, `IMG_2262`）**：按月汇总 `流出 RM181.40 | 流入 RM48.40`，下方按日期卡片分组展示该账户下的有效收支与转账流水。

### 5.3 预算管理与动态日预算算法（1:1 还原 `IMG_2240`, `IMG_2263`, `IMG_2264`, `IMG_2266`）
- **月度总预算与分类预算**：
  - 支持设定月度总预算（如 `RM3,200.00`）和多个一级分类预算（如 `休闲娱乐 RM50`、`购物 RM200`、`交通 RM400`、`餐饮 RM650`、`家用 RM1,000`、`车贷 RM700`），自动计算 `未分类预算 = 总预算 - 已分配分类预算之和` 及未分类已用金额。
- **动态日预算（今日可用）计算逻辑**：
  - 首页右上角彩色圆环内的「今日可用」与预算管理页底部的「动态日预算日历」实时联动：
  - 设当月剩余含今日天数为 $D_{\text{remain}}$，截至昨日累计支出为 $S_{\text{past}}$，月总预算为 $B_{\text{month}}$，则今日及未来每日基准动态可用额度为：
    $$\text{DailyBudget} = \max\left(0, \frac{B_{\text{month}} - S_{\text{past}}}{D_{\text{remain}}}\right)$$
  - 在「动态日预算日历」中：今天之前的日期显示当日实际支出（如 `-RM7.70`），今天同时显示今日已花（`RM0.00`）与今日可用预算（`RM92.26`），未来日期以浅灰字显示动态分配的每日可用预算（`RM92.26`），并支持点击查看当日花费或长按单独编辑某天日预算。

### 5.4 快捷指令自动截屏 -> 确认/修改闭环（`IMG_2294` + 用户定制要求）
- **快捷指令工作流**：
  1. App 内置 `AppIntents` 动作 **`识别截屏记账 (ScanScreenshotIntent)`**，并在「自动记账 / 快捷记账」页面提供一键添加/配置系统「快捷指令（自动截屏并送入咔皮记账）」的引导说明。
  2. 当用户在 TNG eWallet / PBBank / 微信 / 支付宝付款成功界面触发快捷指令（如轻点背面两下或按 Action Button）时：
     - 快捷指令自动截取当前屏幕并传给 `ScanScreenshotIntent`。
     - `ScanScreenshotIntent` 调用端侧 `Vision` OCR + 账单解析器提取：**金额**（如 `-RM5.90`）、**一级-二级分类**（如 `餐饮-零食甜品`）、**付款账户**（如识别出 `TNG eWallet` 自动匹配 `TNGewallet`）、**商户/交易方与备注**（如 `Near Me Voucher Eggette Lab`）、**账单时间**。
     - 立即在当前屏幕顶部弹出 `IMG_2294` 同款 `SnippetView` 交互卡片（或快捷指令双按钮弹窗）：
       - **点击右侧蓝色「确认 / Got it」按钮**：直接将该笔账单正式写入当前账本并更新账户余额与审计明细，收起弹窗，全程无需离开当前支付 App。
       - **点击左侧灰色「修改 / View」按钮**：将该笔识别结果暂存为待编辑账单并通过 URL Scheme / `openAppWhenRun` 直接唤醒打开「咔皮记账」App，自动弹出该笔账单的「账单详情 / 编辑」弹窗（所有识别字段与原截图均已预填好），方便用户修改分类、金额或备注后保存。
